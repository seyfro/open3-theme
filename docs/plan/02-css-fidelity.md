## 1. CSS file architecture

```
open3/
  style.css                       header only (Theme Name, Text Domain: open3, Requires PHP 8.1, …) — NOT enqueued
  theme.json                      tokens/palette/fonts (see §7)
  assets/fonts/                   Archivo-400-latin.woff2, Archivo-400-latin-ext.woff2,
                                  Archivo-800-latin.woff2, Archivo-800-latin-ext.woff2  (+ OFL.txt)
  assets/css/design-system.css    adapted copy of ds styles.css (tokens + components, §1.1)
  assets/css/theme.css            all page-level CSS translated from dc.html inline styles (§2) + WP CSS (§6) + @media print
  assets/css/editor.css           block-editor canvas styles (§6.5)
  assets/css/treemap.css          Stage 2 only, enqueued in single-projekt-{sparpaket,wien-budget-2009-visualisierung,…}.php
  assets/js/main.js               menu toggle + explorer (§8), no deps, defer
  assets/js/treemap/              Stage 2: jit-treemap-c.js, budgetkuerzungen-2011-2014-v3.1.js, gesamthaushalt-2011-2014-v1.0.js, wien-budget2009-ausgaben.js (excanvas.js dropped)
```

**Load order (wp_enqueue_scripts):** `open3-design-system` → `open3-theme` (deps: `open3-design-system`, `wp-block-library`, and `global-styles` if `wp_style_is('global-styles','registered')`). No `@layer`: WP prints theme.json global styles and block-library CSS unlayered; anything of ours inside a layer would lose to them regardless of specificity. Plain source order + dependency chain is deterministic and sufficient. `@font-face` is not a separate file: it is generated by WP from `theme.json → fontFace` (`wp_print_font_faces`, WP ≥ 6.4, prints on front end and in the editor iframe), plus two `<link rel="preload" as="font" type="font/woff2" crossorigin>` for the latin 400/800 files from `wp_head`. Print styles: a short `@media print` block at the end of theme.css (no separate file).

## 3. Responsive strategy

- Container 1280px centered; body background = `--color-bg` so the frame is seamless on wide screens; the 2px rules span the container only (dc:553).
- Page padding `--o3-pad: clamp(16px,4vw,48px)`; column gap 40px; grids always `minmax(min(100%, N), 1fr)` (C-6), footer `auto-fit`, project grid `auto-fill`.
- **Single breakpoint 900px** for columns AND nav. Derivation: flex bases 560 + 260 = 820px; with 4vw padding each side the natural wrap point is 820/0.92 ≈ 891px. At ≥900px the inner width is ≥ 828px, so two columns always fit; forcing the desktop/mobile switch at 900 means the visual state (borders, paddings) never disagrees with the wrap state. The mobile menu shares the breakpoint because the toggle only makes sense once the sidebar is stacked (both are "narrow layout"); see §2.2 note on the 900-1160 nav wrap.
- Mobile: aside under main, `border-top: 2px`, `padding-top:8px` (dc:555), search block keeps `padding-top:40px` (48px total to "Suche", symmetric with the 48px pagination bottom padding).
- Touch targets: mobile menu items 14px+16px×1.55+14px ≈ 53px; buttons 36px + surrounding gap; pagination and filter chips get an invisible `::before` hit-area extension to ≥44px without changing the drawn box.
- `sidebarPosition=links`: Customizer setting `open3_sidebar_position` (`rechts|links`, default rechts) → `body_class` adds `o3-sidebar-left`; CSS delta is only the ≥900px block in §2.2 (order + padding side + border side, dc:554-555).
- Prefer `@media (min-width: 900px)` and `(max-width: 899.98px)` pairs; no container queries needed.
